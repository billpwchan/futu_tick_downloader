# 09-收盘后自动发布、归档与本地镜像

当前生产链路以 JChart 的已验证 Futu ZIP 为跨项目边界，不再要求人工批量导出 SQLite、下载
`*.backup.db`、本地转换后再删除服务器日库。

## 运行顺序

| 香港时间 | 所属项目 | 操作 |
| --- | --- | --- |
| 18:10 | JChart | 只读快照 collector 的 DB + WAL，校验后原子发布 `YYYYMMDD.zip` 与 manifest |
| 18:30 | futu_tick_downloader | 生成可恢复的 `db.zst` 归档，并执行 14 天原始日库保留策略 |
| 19:00 | JChart 本机 | 只下载带有效 manifest 的缺失 ZIP，复核 SHA-256 与 ZIP CRC 后写入本机 staging |

三个任务使用不同锁，均为幂等操作。JChart 发布必须先于 collector 归档；本地镜像只消费 JChart
发布物，不直接读取或删除服务器 SQLite。

## 服务器端 collector 归档

安装并启用 canonical timer：

```bash
cd /opt/futu_tick_downloader
sudo bash deploy/scripts/install_eod_archive.sh
sudo systemctl disable --now hk-tick-archive.timer 2>/dev/null || true
sudo systemctl enable --now hk-tick-eod-archive.timer
```

`/etc/hk-tick-eod-archive.env` 建议值：

```dotenv
REPO_ROOT=/opt/futu_tick_downloader
DATA_ROOT=/data/sqlite/HK
ARCHIVE_DIR=/data/sqlite/HK/_archive
RAW_KEEP_DAYS=14
```

核验：

```bash
sudo systemd-analyze verify hk-tick-eod-archive.service hk-tick-eod-archive.timer
systemctl list-timers --all hk-tick-eod-archive.timer
sudo journalctl -u hk-tick-eod-archive.service --since today --no-pager
```

休市日没有当日 DB 时返回 `SKIP day=... reason=db_not_found`，属于正常结果。不得重新启用旧的
`hk-tick-archive.timer`；旧 unit 的 CLI 参数顺序错误，并与当前发布顺序冲突。

## JChart 发布与本地镜像

JChart 服务器发布任务由以下入口维护：

```bash
/opt/jchart/app/scripts/install_hk_collector_publish_timer.sh verify
systemctl list-timers --all jchart-hk-collector-publish.timer
```

本机镜像任务由 JChart 仓库安装：

```bash
cd /Users/billpwchan/Documents/JChart_Nov
./scripts/install_local_hk_history_mirror.sh install
./scripts/install_local_hk_history_mirror.sh verify
```

macOS 后台任务先写入 `~/Library/Application Support/JChart/history-mirror`，避免要求 Full Disk Access；
下次启动本地 JChart 时，前台启动器会再次验证并提升到默认目标 `/Volumes/NVME4000G/HK Tick Data`。
同步器拒绝覆盖同日但哈希不同的本地文件，也不会删除服务器归档或本机历史数据。日志位于
`~/Library/Logs/JChart/`。

## 故障边界

- JChart 发布失败：保留 collector DB/WAL 与既有 ZIP，修复后重跑发布；不得先清理源文件。
- collector 归档失败：JChart 已发布 ZIP 仍可用，保留源 DB 并调查 service 日志。
- 本地镜像失败：服务器发布物不受影响，下次任务仅补下载缺失日期。
- SHA-256、CRC、schema、市场、日期或行数任一验证失败：停止该日期，不覆盖既有正确产物。

旧的“全量导出 → scp backup.db → 本地转换 → `rm -f` 日库”流程仅作为灾难恢复手段保留，不再用于
日常维护。任何源库清理都必须由已验证的归档策略完成，不能对 collector 正在持有的 DB/WAL 执行外部删除。
